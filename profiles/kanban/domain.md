# Domain — Kanban 0 → Experto

## Propósito

Este PATH forma desde cero hasta un nivel avanzado en Kanban como método de gestión
evolutiva para trabajo de conocimiento y servicios. No reduce Kanban a visualización
de tareas: integra diseño de sistemas, flujo, demanda, riesgo, métricas, forecasting,
orientación al cliente, upstream, portfolio y evolución empresarial.

## Columna vertebral

Los tres dominios principales se integran, no se estudian como cursos aislados:

- **Discovering Kanban** aporta la visión sistémica y evolutiva: servicios, flujo,
  cambio evolutivo, feedback, madurez y organización como red de servicios.
- **Upstream Kanban** extiende el sistema antes del commitment point: demanda,
  opciones, discovery, selección, riesgo, replenishment y portfolio.
- **Fit for Purpose (F4P)** conecta el sistema con los resultados que importan al
  cliente mediante propósito, segmentos contextuales, fitness criteria,
  expectativas y métricas de fitness.

Modelo conceptual:

Customer need → Fitness criteria → Demand → Options → Discovery → Selection →
Commitment → Delivery Kanban → Outcome → Customer feedback → evolución.

## Alcance obligatorio

El curso debe cubrir pensamiento sistémico; servicios; principios y prácticas Kanban;
visualización; WIP; pull; políticas; clases de servicio; métricas de flujo; CFD;
aging; Little's Law; SLE; forecasting probabilístico y Monte Carlo; cadencias;
STATIK; service delivery; F4P; Upstream Kanban; demand management; optionality;
discovery; commitment; replenishment; portfolio; riesgo; cost of delay; redes de
servicios; Enterprise Kanban; analítica y troubleshooting.

## Reglas pedagógicas

Cada lección empieza con `🎯 OBJETIVO` y termina con
`🧠 QUÉ DEBES RECORDAR`, con 3–7 ideas esenciales. Cuando aporten valor deben
aparecer `🧪 Laboratorio/ejemplos`, `⚠️ Errores frecuentes` y
`💡 Idea importante`.

Las lecciones deben explicar primero el modelo mental, después mecanismo y
consecuencias, después aplicación. Deben evitar recetas descontextualizadas.
Los ejemplos deben conectar progresivamente con un sistema de servicios que
evoluciona durante el PATH.

## Profundidad

Nivel inicial: vocabulario, sistemas, servicios, flujo y fundamentos Kanban.

Nivel intermedio: diseño mediante STATIK, políticas, WIP, métricas, cadencias,
service delivery, F4P y upstream.

Nivel avanzado: forecasting, riesgo, portfolio, redes de servicios, madurez,
evolución organizacional y analítica.

Nivel experto: diagnóstico de sistemas, decisiones bajo incertidumbre,
Enterprise Kanban y diseño de un sistema end-to-end que conecte demanda con
customer outcomes.

## Límites conceptuales

No presentar Kanban como Scrum con un tablero.
No equiparar actividad con valor.
No usar utilización individual como objetivo de optimización.
No convertir SLE en promesa determinista.
No presentar Monte Carlo como certeza.
No tratar upstream como backlog infinito.
No imponer prácticas avanzadas sin contexto.
No usar métricas para ranking de personas.
No confundir prioridad con commitment.
No asumir que maximizar throughput maximiza fitness for purpose.

## Proyecto integrador

El proyecto final construye un Enterprise Kanban System completo: red de servicios,
STATIK, upstream, discovery, commitment, delivery, F4P, métricas, SLE, forecasting,
riesgo, portfolio, cadencias y un plan explícito de evolución.
