# Bibliografía — Git 0 → Experto

Las ediciones y el soporte de funciones deben contrastarse con la documentación de la versión de Git instalada.

## Fundamentos
- **Pro Git — Scott Chacon, Ben Straub** — https://git-scm.com/book/en/v2
- **Learning Git: A Hands-On and Visual Guide to the Basics of Git — Anna Skoulikari**

## Fundamentos y CLI
- **Git Pocket Guide — Richard E. Silverman**

## Internals y operaciones
- **Version Control with Git, 3rd Edition — Prem Kumar Ponuthorai y Jon Loeliger**

## Práctica profesional
- **Git in Practice — Mike McQuaid**

## Equipos y colaboración

## Arquitectura
- **Git Internals — Scott Chacon**

## Normativa CLI
- **Git Reference Manual** — https://git-scm.com/docs

## Arquitectura y protocolos
- **Git Technical Documentation** — https://github.com/git/git/tree/master/Documentation/technical

## Seguridad y mantenimiento
- **Git upstream documentation** — https://github.com/git/git

## Distribución por scopes
- Bloques 0–20: Pro Git, Git Pocket Guide, Git in Practice, Git for Teams.
- Bloques 21–33: Version Control with Git, Pro Git y manual de comandos.
- Bloques 34–45: Git Internals, documentación técnica y manual oficial.
- Bloques 46–55: manual oficial, documentación upstream y documentación de las plataformas.
- Bloques 56–65: documentación técnica upstream, código fuente y manual oficial.

## Referencias oficiales por competencia
La documentación de la versión instalada prevalece para opciones, formatos y
comportamiento. Los libros aportan explicación y ejercicios; los textos
históricos de internals deben contrastarse con upstream. No asumir que un
backend o una opción reciente está disponible sin comprobar capacidades.
